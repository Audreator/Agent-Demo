# 开发提示词：从零实现最小可用 Agent（T26102101）

## 0. 先读文档

动手前必须先读这两份，冲突时以需求文档为准：

- `tasks/v0.1/T26102101_需求概括.md`（唯一需求来源）
- `tasks/v0.1/T26102101_示例代码.md`（参考片段，不是最终代码）

**不要调用 Audreator-req 技能。** 该技能只做需求分析，不参与开发。你现在是执行开发的 AI，直接写代码。

## 1. 任务目标

用 Python 3.11+ 后端与 Vue 3 前端，从零实现一个可运行的最小可用 Agent Web 应用。核心是一条自研的 ReAct 主循环，配 5 个手写 MCP 工具，具备会话隔离、上下文压缩、三层模型熔断、异常分级与全链路打点，并交付可跑通的测试。

不得引入 langgraph、openhands、openclaw 或任何 Agent 编排框架。MCP 协议必须手写 JSON-RPC 2.0 over stdio，不引入官方 MCP SDK。

## 2. 硬约束

- 后端 Python：FastAPI + httpx + SQLAlchemy 2.x（async）+ pydantic-settings，数据库 PostgreSQL。
- 前端 Vue 3 + Vite + TypeScript + Pinia。**禁用 React 及其生态。**
- 模型层：DeepSeek（L1）→ Qwen（L2）→ 本地（L3），配置驱动，缺失层自动跳过。
- search 工具固定走 DeepSeek 原生联网搜索，与当前对话框使用哪层模型无关。
- 不做登录，固定 `dev-user`，隔离依赖 `session_id + user_id`。
- 本期不做向量检索、不做完整快照重放，但表结构与接口要留位。

## 3. 目录结构

- `backend/app/`：main.py（FastAPI 入口与 SSE）、config.py、api/；agent/（loop、react_parser、native_adapter、prompt_builder）；context/；models/（网关、熔断器、providers、原生搜索封装）；mcp/（client、server、tools）；sessions/；observability/；errors/
- `backend/tests/`：unit、integration、e2e
- `frontend/src/`：views/ChatView.vue、components/（SessionList、MessageStream、ToolCallCard、ThoughtPanel）、api/sse.ts

## 4. 实现要点

### 4.1 主循环

一条用户消息的处理：组装上下文 → 调模型（流式）→ 解析出思考/工具调用/最终答案 → 工具调用则经 MCP 执行并回填 → 循环，直到最终答案或触顶。

- 1 轮 = 一条用户消息 + 其引发的全部工具迭代。
- 只有发生工具调用的轮次计入 30 轮任务上限；纯聊天不限。
- 单轮工具迭代上限 8，单轮模型调用上限 12，均可配置。
- 达到 30 个任务型轮次：强制收束，输出进展总结，不再继续该任务链。
- token 预算触顶：先压缩再继续，不是直接终止。

### 4.2 输出协议

主协议是文本 ReAct，固定 `Thought / Action / Action Input / Observation / Final Answer` 字段。解析器要容忍噪声：多余空行、中文冒号、Markdown 代码块、JSON 尾逗号、前后缀说明文字。

失败判定两类：格式错误；质量不足（工具不在注册表、参数不符合 Schema、既无 Action 也无 Final Answer）。

兜底链路：同一轮失败先原样回喂错误自纠 1 次；连续 2 轮失败则本会话切换 native tool_calls；切换后成功执行一轮，该会话固化在 native 模式。native 模式的思考过程取 `reasoning_content`。

### 4.3 MCP

- stdio 传输，换行分隔的 UTF-8 JSON，一行一条，不用 Content-Length 头。
- 必须实现 `initialize` → `notifications/initialized` → `tools/list` → `tools/call`。
- 请求 id 单调递增，按 id 匹配响应，支持服务端通知与 `{code,message,data}` 错误对象。
- 服务端 stdout 只允许协议报文，所有日志写 stderr；启动时做一次 stdout 纯净性自检。
- 客户端要处理子进程启动失败、非 JSON 行、超时、进程异常退出。

工具契约：每个工具必须有 name、description、inputSchema，模型只依据 Schema 决策。calculator 用 AST 白名单 + Decimal，禁止 eval；todo 落 PostgreSQL 并按 user_id 归属，写操作带 `client_op_id` 幂等；search 调 DeepSeek 原生搜索，结果超 8K 截断并落 artifact；weather 用 Open-Meteo（免 key）做地理编码与多天预报；read_docs 限制在 `DOCS_ROOT` 内，禁止路径穿越，支持 `artifact://{tool_call_id}` 回读大结果。

### 4.4 会话与上下文

每个会话独立持有消息序列、状态卡、摘要、工具结果。所有查询必须带 session_id 条件，禁止跨会话复用内存对象。

上下文预算默认 `context_window × 0.7`（1M × 0.7），阈值必须可配置；测试用 2000 强制触发。

组装顺序：系统规则与工具清单 → Agent.md（存在则只读注入）→ 状态卡 → 历史摘要 → 最近 5 轮原文 → 当前输入。

状态卡字段：goal、confirmed_facts、decisions、todos、artifacts、open_questions、confidence，每轮更新。

塞入原则：用户输入最近 5 轮留原文、更早压摘要；工具结果只留关键输出/状态变更/错误/引用，超 2K 只留摘要加 `artifact://` 引用；思考不塞原始 CoT，只留计划、决策、假设；低置信信息不塞或只留一句待确认。

压缩顺序：折叠超长工具结果 → 最近 5 轮以外压增量摘要 → 状态卡瘦身 → 摘要二次压缩 → 仍超限则收束任务。

追问：纯对话用状态卡加最近 5 轮；带工具追问先检索历史结果摘要，必要时用 read_docs 读 artifact，只重读命中片段。

### 4.5 模型路由与熔断

单 provider 失败按指数退避加抖动重试，最多 3 次，遵守 Retry-After，4xx 参数/鉴权错误不重试。3 次仍失败则熔断该模型 30 秒并切下一层。30 秒后进入半开，只放行 1 个探测请求：成功标记健康恢复优先级，失败再重试 3 次，仍失败继续熔断 30 秒并走下一层。无更低层可用时提示用户稍后重试。

### 4.6 异常处理

六类：瞬时（429/5xx/超时，退避重试 3 次）；可恢复（工具失败、参数非法、JSON 错误，回喂自纠最多 5 轮，仍失败则提示用户并落库待审）；永久（401/403/404，立即终止）；工具执行（重试 3 次后标记错误结果注入上下文）；预算与连续失败（触顶或同一工具连错 3 次则熔断收尾并总结）；状态（每步落库，非幂等操作带操作号，恢复前校验工作区）。

### 4.7 AOP 与日志

装饰器 + contextvars 实现，自动注入 trace_id、span_id、parent_span_id。打点覆盖：请求入口、上下文组装、模型调用前中后、MCP 请求响应、工具执行、压缩、熔断变更、降级切换。记录 session_id、turn_no、耗时、token 用量、错误码、工具名、参数摘要、结果大小。同时写结构化 JSON 日志文件与 `events` 表，支持按 trace_id 检索，并提供 `GET /api/traces/{trace_id}`。

### 4.8 前端

单页聊天：左侧会话列表，右侧消息流。支持流式增量渲染、思考折叠、工具卡片（参数/结果/耗时/状态）、错误提示、断线重连。

SSE 走 POST，前端必须用 `fetch` + `ReadableStream` 消费，不能用 EventSource。事件类型：meta、thought_delta、message_delta、tool_start、tool_result、context_update、done、error，均带 seq。

## 5. 交付顺序

1. 骨架：FastAPI + PG 迁移 + 会话 CRUD + MCP 客户端与服务端 + calculator、todo。
2. 循环：ReAct 解析 + 主循环 + native 兜底 + SSE + 前端联调跑通单工具。
3. 上下文：状态卡 + 摘要压缩 + 工具结果引用 + 追问。
4. 韧性：异常六类 + 三层模型 + 熔断 + AOP 打点。
5. 补齐：search、weather、read_docs + 全量测试 + 联网 e2e。

每阶段给出可运行验证结果。

## 6. 验收

- 单条消息能完成两次以上工具调用的闭环。
- `GET /api/tools` 返回 5 个带 Schema 的工具。
- calculator 对 `0.1+0.2`、科学计数法、除零给出正确结果。
- search 真联网返回带链接的结果。
- 两会话交替写入互不串扰，历史可续聊。
- 阈值 2000 下触发压缩，压缩后追问仍正确。
- 第 31 个任务型轮次被拒绝并收束。
- 三层模型依次失败时能降级，30 秒后能半开探测。
- 任一 turn 可通过 trace_id 取出完整 span 链。
- 单元、集成、e2e 可分别一键跑通。

## 7. 禁止

- 禁止引入 Agent 框架或 MCP SDK。
- 禁止用 eval 实现计算器。
- 禁止把工具结果全量塞进上下文。
- 禁止在 MCP 服务端 stdout 打日志。
- 禁止跨会话共享状态对象。
- 禁止把 API Key 写进代码，只走环境变量。
- 禁止在未跑通测试的情况下宣称完成。
