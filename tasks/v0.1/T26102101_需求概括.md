## 1. 一句话目标

用 Python 后端 + Vue 前端，从零实现一个可运行的最小可用 Agent Web 应用：具备 ReAct 主循环、5 个手写 MCP 工具、会话隔离、上下文压缩、三层模型熔断、异常分级、全链路打点，并配套可执行的测试用例。

---

## 2. 成功标准（按优先级）

1. 单条用户消息可完成完整闭环：思考 → 调用工具 → 读取结果 → 继续思考或输出最终答案。
2. 至少 3 个工具可用；calculator、todo 必须真实可用，search 必须真联网返回结果。
3. 同一用户两个会话窗口互不串扰，历史可随时续聊。
4. 上下文超阈值时能自动压缩，压缩后仍能正确回答追问。
5. 模型层故障时自动降级到下一层，30 秒后进入半开探测。
6. 每一次模型调用、工具调用都有可检索的 trace 日志。
7. 自动化测试覆盖核心链路，含一个真联网 e2e 用例。

## 5. 系统架构

```
Vue3 前端
   │  POST /api/sessions/{id}/messages  (SSE)
   ▼
FastAPI 接入层
   │
   ├── AgentLoop ── ReActParser ── NativeToolCallAdapter
   │       │
   │       ├── ContextManager（状态卡 / 摘要 / 预算）
   │       ├── ModelGateway（三层路由 / 熔断器）
   │       │        └── DeepSeekWebSearch（search 工具的后端）
   │       └── MCP Client（手写 JSON-RPC 2.0 / stdio）
   │                 │
   │                 ▼
   │           MCP Server（子进程，单进程 5 工具）
   │
   ├── SessionService / Repository（PostgreSQL）
   └── Observability（AOP 装饰器 / trace / events 表 / 日志文件）
```

进程模型：Web 服务 1 个；MCP Server 由客户端按需拉起为 1 个子进程（stdio 管道）。MCP Server 的 stdout 只允许输出协议报文，所有日志写 stderr。

## 6. 模块需求详解

### 6.1 Agent 主循环

单轮用户消息的处理流程：

1. 接收用户输入，落库，生成 `trace_id`。
2. 组装上下文（见 6.4）。
3. 调用模型，读取流式输出，累积完整文本。
4. 解析模型输出，得到以下之一：思考过程、工具调用、最终答案。
5. 若为最终答案：流式返回用户，结束本轮。
6. 若为工具调用：经 MCP Client 执行，结果写入上下文，回到第 3 步。
7. 迭代达到上限或预算触顶时，收束并输出进展总结。

边界定义：

- **1 轮（turn）** = 一条用户消息 + 其引发的全部工具迭代。
- **任务型轮次** = 该轮内至少发生 1 次工具调用；仅此类轮次计入 30 轮上限。
- **单轮最大工具迭代次数**：8（可配）；**单轮最大模型调用次数**：12（可配）。
- 达到 30 个任务型轮次：强制收束该任务，输出进展总结，不允许继续该任务链。
- token 预算触顶：先压缩，再继续（不是直接收束）。

### 6.2 模型输出协议（ReAct 为主，原生调用兜底）

主协议为文本 ReAct，固定格式：

```
Thought: <推理>
Action: <工具名>
Action Input: <JSON 对象>

（工具执行后回填）
Observation: <工具结果>

...（可重复）

Thought: <推理>
Final Answer: <最终答案>
```

解析规则：

- 解析器需容忍多余空行、中文标点、JSON 前后缀噪声、Markdown 代码块包裹。
- `Action Input` 先按 JSON 解析，失败时尝试修复（去尾逗号、补括号、提取首个平衡括号块）。
- **失败判定**：格式错误 或 质量不足。质量不足定义为：Action 不在工具注册表、参数不符合 Schema、既无 Action 也无 Final Answer。

兜底策略（用户已确认）：

1. 同一轮解析失败 → 原样回喂错误信息给模型自纠 1 次。
2. 连续 2 轮仍失败 → 该 session 切换为 native tool_calls 模式。
3. 切换后成功执行一轮 → 该 session 后续保持 native 模式，不再回切。
4. native 模式的思考过程取自 `reasoning_content` 字段。

### 6.3 工具与 MCP

**协议层（自研 JSON-RPC 2.0 over stdio）**

- 消息以换行分隔的 UTF-8 JSON，一行一条；不使用 Content-Length 头。
- 必须实现的交互序列：
  1. `initialize`（携带 protocolVersion / capabilities / clientInfo）
  2. `notifications/initialized`
  3. `tools/list`
  4. `tools/call`
- 请求 id 单调递增；响应按 id 匹配；需支持服务端通知与错误对象 `{code, message, data}`。
- 客户端需处理：子进程启动失败、非 JSON 输出行、超时、进程异常退出。

**工具注册机制**

每个工具声明：`name`、`description`、`inputSchema`（JSON Schema）。模型仅依据 Schema 决策。工具清单：

| 工具 | 必做 | 关键要求 |
|---|---|---|
| calculator | 是 | 精确计算，支持科学计数法，禁用 eval |
| todo | 是 | 增删改查，PostgreSQL 持久化 |
| search | 是 | 走 DeepSeek 原生联网搜索，返回标题/链接/摘要 |
| weather | 是 | 当天与多天预报，免 key 数据源（Open-Meteo） |
| read_docs | 是 | 受限于文档根目录，支持分段读取与大结果回读 |

**calculator**

- 入参：`expression`、`precision`（默认 28）、`notation`（auto/scientific/fixed）。
- 实现：`ast.parse` 白名单节点求值（BinOp/UnaryOp/Constant/括号），Decimal 运算；禁止 `eval`、函数调用、属性访问、下标。
- 输出：结果值、格式化字符串（科学计数法保留），错时返回明确错误原因。

**search**

- 入参：`query`、`max_results`（1-10）、`recency_days`（可选）、`site`（可选）。
- 后端：调用 DeepSeek 原生联网搜索能力，无论当前对话使用哪层模型，search 工具固定走 DeepSeek。
- 输出：结构化结果列表；总长度截断到 8K 字符以内，超长部分落 artifact。

**weather**

- 入参：`location`、`days`（1-7）、`units`（metric）。
- 流程：地名 → 地理编码（Open-Meteo Geocoding）→ 预报接口 → 归一化为中文描述。
- 地名解析失败时，允许降级调用 search 辅助确认地点，但不得无限递归。

**read_docs**

- 入参：`path` 或 `ref`、`offset`、`limit`（默认 4K 字符）。
- 安全：限制在 `DOCS_ROOT` 内，禁止路径穿越与符号链接逃逸。
- 支持 `artifact://{tool_call_id}` 引用，用于回读被截断的大工具结果。

**todo**

- 入参：`action`（create/list/update/complete/delete）、`id`、`content`、`due_at`、`status`、`client_op_id`。
- 持久化到 PostgreSQL，按 `user_id` 归属，记录来源 `session_id`。
- 写操作携带 `client_op_id` 做幂等，重复提交不产生重复记录。

### 6.4 会话管理

- `session_id` 使用 UUID，全局唯一；每个会话独立的状态卡、摘要、消息序列、工具结果。
- 用户可在任意会话间切换并续聊，互不影响；所有查询必须带 `session_id` 条件。
- 会话记录：标题、创建时间、最后活跃时间、当前输出模式（react/native）、状态。
- 前端会话列表按最后活跃时间倒序。

### 6.5 上下文管理

**上下文预算**

- 预算 = `context_window × 0.7`（默认 1,000,000 × 0.7 = 700,000 token）。
- 触发阈值可配置覆盖；测试环境用低阈值（如 2,000）强制触发压缩分支。
- 估算方式：字符数 / 1.6 作为快速估算，允许 ±15% 误差。

**组装顺序（每次调用模型前重建）**

```
[System] 角色与规则 + 工具清单 + ReAct 格式约束 + 异常处理策略
[System] Agent.md（如存在，只读注入）
[System] 状态卡（结构化，紧凑 JSON）
[System] 历史摘要（覆盖早期轮次）
[最近 5 轮原文]  用户 / 助手 / 工具调用与结果（关键部分）
[当前用户输入]
```

**状态卡字段**

`goal`（当前目标）、`confirmed_facts`（已确认事实）、`decisions`（关键决策）、`todos`（待办）、`artifacts`（产物/文件引用）、`open_questions`（待确认假设）、`confidence`（置信度）。每轮结束后更新，跨轮持久化。

**塞入原则（用户已确认）**

| 类型 | 策略 |
|---|---|
| 用户输入 | 最近 5 轮保留原文，更早压成摘要 |
| 工具结果 | 只塞关键输出、状态变更、错误与引用路径；超过 2K 字符的结果只留摘要 + `artifact://` 引用 |
| Agent 思考 | 不塞原始 CoT；只保留计划、决策、假设，并标注置信度 |
| 低置信信息 | 不塞，或仅保留一句带“待确认”标记 |

**追问策略**

- 纯对话追问：状态卡 + 最近 5 轮原文即可。
- 带工具追问：先检索历史工具结果摘要与产物引用；需要细节时通过 `read_docs` 读 `artifact://`，只重读命中片段。

**压缩规则（按序执行，直到低于阈值）**

1. 折叠超长工具结果为摘要 + 引用。
2. 将最近 5 轮以外的原文压缩为增量摘要，合并进历史摘要。
3. 状态卡瘦身（去重、合并同类事实）。
4. 仍超限：对摘要做二次压缩。
5. 压缩后仍超限：收束当前任务并提示用户。

### 6.6 三层模型路由与熔断

- 层序：DeepSeek（L1）→ Qwen（L2）→ 本地模型（L3）。
- 配置驱动，任一可用即可启动；缺失的层自动跳过。
- 单个 provider 调用失败：指数退避 + 抖动，最多 3 次；遵守服务端 `Retry-After`；4xx 参数/鉴权错误不重试。
- 3 次仍失败 → 熔断该模型 30 秒 → 切下一层。
- 熔断期间请求直接走下一层；30 秒后半开，放行 1 个探测请求：
  - 成功 → 标记健康，恢复该层优先级。
  - 失败 → 再重试 3 次，仍失败则继续熔断 30 秒并走下一层。
- 无更低层可用 → 向用户返回“服务暂不可用，请稍后重试”。

### 6.7 异常处理（六类）

| 类别 | 判定 | 处理 |
|---|---|---|
| 瞬时 | 429/5xx/超时/连接失败 | 指数退避 + 抖动，最多 3 次，遵守等待提示 |
| 可恢复 | 工具失败、参数非法、JSON 解析错 | 原样回喂模型自纠，最多 5 轮；仍失败则友好提示 + 落库待人工审查 |
| 永久 | 401/403/404/权限不足/资源不存在 | 立即降级或终止，不重试 |
| 工具执行 | 工具抛错或返回 isError | 最多重试 3 次，统一标记为错误结果并附原因注入上下文 |
| 预算/连续失败 | 预算触顶，或同一工具连续失败 3 次 | 熔断收尾，输出进展总结 |
| 状态 | 进程中断、写库失败、重放风险 | 每步落库状态；非幂等操作带唯一操作号；恢复前校验工作区 |

补充：同一工具在本任务内连续失败 3 次后禁用该工具，不得继续调用。

### 6.8 AOP 与可观测

- 以装饰器 + contextvars 实现，自动注入 `trace_id`、`span_id`、`parent_span_id`。
- 打点范围：请求入口、上下文组装、模型调用前/中/后、MCP 请求/响应、工具执行、压缩、熔断状态变更、降级切换。
- 每条记录包含：session_id、turn_no、耗时、token 用量、错误码、工具名、参数摘要（脱敏）、结果大小。
- 落两处：结构化 JSON 日志文件（按天切分）+ PostgreSQL `events` 表（可按 trace_id 检索）。
- 前端可通过 `GET /api/traces/{trace_id}` 查看链路，便于排查。

### 6.9 前端

- 页面：单页聊天，左侧会话列表，右侧消息流。
- 消息流支持：流式增量渲染、思考过程折叠、工具调用卡片（参数/结果/耗时/状态）、错误提示。
- SSE 事件：`meta` / `thought_delta` / `message_delta` / `tool_start` / `tool_result` / `context_update` / `done` / `error`。
- 后端 SSE 接口为 POST，前端须用 `fetch` + `ReadableStream` 消费，不能使用 EventSource。
- 断线重连：携带 `seq` 或 `Last-Event-ID` 续传。

## 10. 测试要求

**单元测试**：calculator 精度与非法表达式、ReAct 解析器（含噪声输入）、JSON 修复、上下文压缩、状态卡更新、异常分类、熔断状态机、MCP 报文编解码。

**集成测试（Fake LLM，不依赖网络）**：
- scripted 模型按脚本返回，验证完整 loop。
- 两会话并发交错，断言无串扰。
- 低阈值（2000）强制触发压缩，验证压缩后追问仍正确。
- 工具连续失败触发重试与禁用。
- 三层模型依次失败，验证降级与半开探测。
- native 兜底切换与模式固化。

**e2e（真网络、真 Key）**：真实 DeepSeek + 真实 search 工具完成一次“查一下今天杭州天气并建个待办”的端到端流程，断言工具调用链与最终答案。

## 11. 验收矩阵

| 需求点 | 验收方式 |
|---|---|

## 12. 风险与解决办法

| 风险 | 影响 | 处置 |
|---|---|---|
| DeepSeek 原生联网搜索的 API 参数形态未定 | search 工具无法落地 | 开发前先写探针脚本验证；若 API 不支持，改为可插拔 HTTP 搜索 provider，保持工具契约不变 |
| ReAct 文本解析对模型格式敏感 | 循环中断 | 容错解析 + 自纠 1 次 + native 兜底；解析器必须有噪声用例 |
| 700K 阈值在真实场景难以触发 | 压缩逻辑无法验收 | 阈值配置化，测试用 2000 强制触发 |
| MCP stdio 的 stdout 被日志污染 | 协议解析失败 | 服务端日志强制走 stderr，并加启动自检 |
| Qwen / 本地模型无可用凭证 | 熔断链路无法验证 | 用 Fake Provider 覆盖状态机，不依赖真实第二层 |
| SSE 为 POST | EventSource 不适用 | 前端用 fetch + ReadableStream，事件带 seq |
| 单用户无鉴权 | 跨用户隔离无从验证 | 明确为 dev 单用户模式，隔离靠 session_id；预留 user_id 字段 |
