## 一、本次实现内容

- 不确定回答拦截：新增拒绝表述判定模块，覆盖中英文常见拒绝说法、200 字符匹配窗口、800 字符上限与链接排除。
- 最终回答缓冲：ReAct 只缓冲 `Final Answer:` 之后的正文，native 缓冲 `content`；思考继续流式；超 20,000 字符立即放行并跳过判定；模型重试时清空缓冲。
- 强制检索：命中后由后端直接执行一次 `search`（query 截断 500、`max_results=5`），复用现有 ToolExecutor/MCP 通道与超时重试；完整落库 `tool_calls`，推送 `tool_start` / `tool_result` 与引用。
- 固定文案兜底：检索为空、报错、超时、工具离线/禁用、开关关闭、30 轮或 8 次上限，统一输出固定文案并以 `final` 落库，带 `forced_search=true`；重答仍拒绝则替换，不再二次强制；预算不足时先检索再走收束。
- 可观测：新增 `search_forced`、`search_forced_skipped`、`forced_answer_replaced` 事件；拒绝原文不进入 SSE、上下文或数据库。
- 首 Token P95：gateway 每次尝试记录 `first_token_ms`，成功写入 `model_success`；`turn` 记录请求入口到首个可见增量的耗时；后台总览、趋势桶、模型分层返回 P95 与样本数，模型侧改为库内聚合。
- 前端：后台新增首 Token P95 卡片、第二 Y 轴折线、模型表列与空值“—”，未新增组件或依赖。

## 二、修复与审查历程

1. 首轮实现后补齐开关关闭、次数上限为 0、30 轮、8 次、预算不足等边界，并统一固定文案与 `forced_search` 标记。
2. 并行三路代码审查共进行 6 轮，主要修复：
   - 开关关闭/次数为 0 时仍拦截并回固定文案；
   - 30 轮场景固定文案改回以 `final` 落库，保留纯聊天不受 30 轮限制的既有行为；
   - 拒绝词表收紧后补充“不知道/不清楚/我不确定/我没找到”等强拒绝表述，匹配改为按起始位置判断；
   - native 拒绝正文与解析错误场景不再进入 SSE、上下文或 `meta.thought`；
   - 缓冲超限后跳过判定，避免半截回答被替换；
   - `_wrap_up` 在强制检索后同样缓冲并替换拒绝文本，meta 补齐 `forced_search` / `replace_reason`；
   - TTFT 排除服务不可用/预算兜底等非模型可见增量；
   - 可访问引用数统一按净化后的 citations 统计；
   - 后台 P95 改为 `percentile_disc` 库内聚合，兼容旧数据与空样本；
   - 移除新增 SSE 字段，错误事件补充 `error` 原因。
3. 最后一轮三路审查均反馈“无严重问题”。

## 三、验收结果

- 后端：`ruff check .`、`mypy app`、`pytest -q` 全部通过（3 个真实网络 e2e 跳过，其余通过）。
- 前端：`npm run typecheck`、`npm run build` 通过，无项目警告。
- 浏览器实测：
  - 提问“我昨天晚饭吃了什么？”时，拒绝回答未展示，先出现 `search` 工具卡片，随后显示固定文案；
  - 数据库确认 action/final 消息 `forced_search=true`、`replace_reason=search_error`，`tool_calls` 为 search error 且重试 2 次，`search_forced` 事件含状态、query 长度、耗时与错误原因；
  - 正常提问仍走普通回答，`forced_search=false`，纯聊天不增加任务轮次；
  - 后台总览、趋势、模型页签的首 Token P95 正常显示；无数据范围全部显示“—”。

## 四、环境说明

- 本机访问 DeepSeek 时存在间歇性 `SSL: CERTIFICATE_VERIFY_FAILED`（自签名证书链），会导致模型调用“服务暂不可用”或搜索失败；该场景已验证重试、熔断与固定文案兜底，属于本机网络/代理环境问题。
