## 三、实现要点

### A. 不确定回答拦截

1. 新增独立判定模块（建议放 `app/agent/` 下）：定义中英文拒绝表述表、匹配窗口、长度与链接排除规则，提供“是否触发强制检索”的纯函数，便于单测。
2. 触发条件必须同时满足：解析为最终回答；本轮没有状态为 `ok` 的 `search`；拒绝表述命中前 200 字符；全文无 `http(s)` 链接；回答不超过 800 字符；本轮未强制过；开关开启；非 `wrap_up` / `parse_error` / `budget_exceeded` / 服务错误兜底。
3. 改造流式分割：`ReAct` 只缓冲 `Final Answer:` 之后的正文，`native` 缓冲 `content`；思考增量继续实时推送。缓冲上限 20,000 字符，超限立即放行并跳过判定；模型重试时清空缓冲。
4. 主循环最终回答分支：不触发则一次性推送 `message_delta` 并落库；触发则不得推送、不得落库原拒绝文本，改为后端直接执行一次 `search`。
5. 强制检索由后端发起，不依赖模型再输出工具调用。参数 `query` 取用户输入去空白后截断 500 字符，`max_results=5`，不传 `recency_days` / `site`。复用现有工具执行器与 MCP 通道，沿用现有超时与重试，不额外加重试。
6. 强制检索必须完整落库 `tool_calls`，推送 `tool_start` / `tool_result`，`tool_result` 带 `citations`；计入一次工具迭代，必要时计入任务型轮次；写入 `search_forced` 事件（触发原因、query 长度、状态、结果数、可访问引用数、耗时）。
7. 检索结果按现有上下文规则压缩后回填 Observation，并按当前模式协议一致追加助手动作消息；原拒绝文本不得进入上下文。随后继续主循环重答，重答正常则放行。
8. 以下情况统一输出固定文案「已尝试联网检索，暂未获取到相关信息。」：检索为空、报错、超时、工具离线、工具被禁用、开关关闭、已达 30 个任务型轮次、单轮工具迭代已达 8 次。固定文案以 `final` 落库并带 `forced_search=true`；同时写 `search_forced_skipped` 或 `error` 状态，内部区分原因。
9. 重答后仍命中拒绝表述：替换为固定文案，写 `forced_answer_replaced` 事件，不再二次强制。每轮最多强制一次。
10. 模型调用预算不足以重答时，仍然先执行检索，再用现有收束流程返回，禁止展示原拒绝文本。
11. 前端不新增组件；强制检索以现有工具卡片与引用列表呈现；最终回答整段到达。历史消息、断线重放、工具汇总、评价均不改。

### B. 首 Token P95

12. 网关发起模型请求时开始计时，收到首个非空增量（content / reasoning / tool_calls）时记录 `first_token_ms`，写入 `model_call` span payload，并在成功时写入 `model_success` payload。重试只以最终成功那次进入统计。
13. 主循环记录“请求入口 → 第一个 `thought_delta` 或 `message_delta`”的耗时，写入 `turn` 事件 payload 的 `first_token_ms`；若产生可见增量前失败则不写。
14. 后台 `GET /api/admin/metrics` 增量返回：
    - `overview.p95_first_token_ms`：轮次首可见 P95；
    - `trend[].p95_first_token_ms`：按桶的轮次首可见 P95；
    - `models[].first_token_p95_ms` 与 `models[].first_token_samples`：按层成功调用 TTFT P95 与样本数。
15. 统计规则：`null` 不计入分母；无样本返回 `null`；复用现有 events 查询，禁止 N+1；范围、时区、粒度沿用现有逻辑。
16. 前端：`AdminView` 总览新增“首Token P95”卡片；`AdminTrend` 新增同名折线（第二 Y 轴，毫秒，空值断点）；模型表格新增“首Token P95”列并在悬浮提示显示样本数；`types.ts` 同步可空字段；空值显示“—”。不新增依赖。
